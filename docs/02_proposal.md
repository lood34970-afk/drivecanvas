# Drive Canvas — GPS 아트 드라이브 기획서 초안

> 문서 상태: 아이디어 검증 전 초안  
> 작성일: 2026-10-30  
> 서비스명: `Drive Canvas`(가칭)  
> 한글 작업명: `길 위에 그리는 드라이브`

## 1. 제안 개요

Drive Canvas는 사용자가 선택한 하트·별·이니셜 같은 모양을 실제 자동차 도로망 위의 주행 가능한 경로로 변환하고, 차량 내비게이션으로 안전하게 안내한 뒤, 실제 GPS 궤적을 하나의 완성 작품으로 남기는 차량용 앱이다.

단순히 지도에 선을 그리는 앱이 아니라 일방통행, 회전 제한, 도로 등급, 좁은 길, 예상 시간과 같은 자동차 주행 조건을 반영해 `그림의 유사도`와 `주행 가능성`을 함께 최적화한다. 운전 중에는 그림 편집과 상세 결과를 숨기고 일반 내비게이션 수준의 최소 안내만 제공한다.

> 내비게이션이 목적지까지의 길만 찾는 것을 넘어, 길 자체를 기억에 남는 콘텐츠로 만든다.

## 2. 기획 배경과 문제 정의

대부분의 내비게이션은 목적지까지 가장 빠르거나 효율적인 이동을 목표로 한다. 그러나 주말 드라이브, 여행, 데이트, 기념일에는 도착보다 이동 과정 자체가 경험의 목적이 되기도 한다. 사용자는 경치 좋은 길을 찾거나 즉흥적으로 경유지를 추가하지만, 주행을 마친 뒤 남는 결과는 사진 몇 장과 이동 기록뿐이다.

GPS 아트는 이동 궤적을 그림으로 남기는 직관적인 놀이지만, 기존 경험은 주로 러닝과 자전거에 맞춰져 있다. 자동차로 직접 경로를 만들려면 일방통행, 좌·우회전 제한, 중앙분리대, 자동차 진입 금지, 좁은 생활도로를 일일이 확인해야 한다. 그림 모양을 유지하려고 무리한 유턴이나 반복 회전을 유도해서도 안 된다.

따라서 핵심 문제를 다음과 같이 정의한다.

> 어떻게 하면 드라이브를 즐기는 사용자가 도로 규칙과 안전을 직접 계산하지 않고도, 원하는 모양에 가까운 경로를 선택해 운전하고 결과를 추억으로 남길 수 있을까?

## 3. 목표 사용자와 사용 상황

### 1차 타깃

- 주말에 30~90분 정도의 목적형 드라이브를 즐기는 운전자
- 기념일이나 여행에서 커플·가족과 특별한 기록을 만들고 싶은 사용자
- 지도 기록과 완주 콘텐츠를 SNS 또는 지인에게 공유하는 사용자

### 대표 사용 상황

- 연인과 기념일에 하트 모양 코스를 달리고 완주 카드를 남긴다.
- 여행지에서 지역 상징 모양 코스를 따라 명소와 로컬 상점을 방문한다.
- 아이와 별·공룡·동물 모양을 고르고 완주 뒤 어떤 그림인지 함께 확인한다.
- 기존 목적지 주변에서 추가 이동을 최소화한 짧은 그림 코스를 선택한다.

## 4. 핵심 가치 제안

### 운전자에게

- 지도 편집 지식 없이도 실행 가능한 GPS 아트 경로를 얻는다.
- 주행 전 예상 시간·거리·난이도·그림 유사도를 비교할 수 있다.
- 운전 중 별도 조작 없이 익숙한 내비게이션 안내를 받는다.
- 완주 뒤 실제 궤적, 달성률, 타임랩스, 공유 카드를 얻는다.

### 동승자에게

- 코스 선택과 완성 그림 맞히기에 참여할 수 있다.
- 지역 명소나 미션을 함께 즐기는 드라이브 놀이가 생긴다.

### 지역·브랜드 파트너에게

- 지역 상징과 명소를 연결한 체류형 관광 코스를 만들 수 있다.
- 축제, 신차 출시, 스포츠 구단, 캐릭터 IP를 완주형 캠페인으로 확장할 수 있다.

## 5. 주요 기능

### 5.1 Canvas Route — 그림 경로 생성

사용자가 출발 지역, 템플릿, 목표 시간 또는 거리를 선택하면 도로망 위에 모양을 투영한다. 후보 경로는 다음 항목을 함께 평가한다.

- 도로 규칙을 지키는 실제 주행 가능성
- 원본 그림과의 형태 유사도
- 전체 거리와 예상 시간
- 급격한 반복 회전, 무리한 유턴, 좁은 골목의 최소화
- 출발지 복귀 또는 지정 목적지 도착 여부
- 선택 시 관광지·충전소·휴게 장소 포함 여부

### 5.2 Route Compare — 후보 비교

출발 전 정차 상태에서 최대 3개의 후보를 비교한다.

- `모양 우선`: 그림 완성도를 높이되 안전 조건은 유지
- `시간 우선`: 목표 시간 안에서 가장 알아보기 쉬운 모양
- `여행 우선`: 명소와 휴식 지점을 포함한 코스
- `에코 우선`: 기존 목적지 주변에서 추가 거리와 에너지 사용 최소화

### 5.3 Safe Guidance — 주행 중 최소 안내

- 차량 내비게이션의 TBT와 음성 안내를 사용한다.
- 주행 중에는 다음 회전, 남은 시간, 전체 진행률처럼 필요한 정보만 제공한다.
- 그림 편집, 후보 재선택, 공유 기능은 정차 상태에서만 허용한다.
- 경로 이탈 시 그림 복원보다 안전한 재탐색을 우선하며, 복원이 어렵다면 완성도 하락을 안내하고 정상 경로로 종료한다.

### 5.4 Reveal & Share — 완주 공개

주행 종료가 확인된 뒤 실제 위치 궤적을 공개한다.

- 목표 선과 실제 궤적 비교
- 완주율과 형태 유사도
- 거리·시간·방문 지점
- 이동 궤적 타임랩스
- 위치를 단순화하거나 숨길 수 있는 공유 카드

### 5.5 Local Canvas — 관광·캠페인 코스

지역 상징과 명소를 묶은 검증된 공식 코스를 제공한다. 예를 들어 고래, 왕관, 섬 윤곽 같은 지역 테마를 사용하고 중간 지점에 관광지·상점·충전소를 배치한다. 자동 생성이 어려운 지역에서도 사람이 검수한 코스로 서비스 품질을 유지할 수 있다.

## 6. 사용자 여정

| 단계 | 사용자 행동 | 앱 동작 | 안전 원칙 |
|---|---|---|---|
| 발견 | 홈에서 추천 그림 또는 지역 코스를 확인 | 현재 위치와 차량 조건에 맞는 후보 표시 | 상세 탐색은 정차 시 제공 |
| 설정 | 그림, 시간, 출발·종료 조건 선택 | 주행 가능한 후보 2~3개 생성 | 위험 도로와 금지 회전 제거 |
| 비교 | 거리·시간·유사도·경유지를 보고 선택 | 선택 경로를 차량 내비게이션에 전달 | 예상 피로도와 휴식 지점 안내 |
| 주행 | 음성·TBT 안내에 따라 운전 | 위치 기록, 진행률 계산, 안전 우선 재탐색 | 편집·공유 잠금, 최소 정보 표시 |
| 완주 | 안전한 정차 후 결과 확인 | 실제 GPS 아트와 완주 카드 생성 | 민감 위치 비공개 기본값 |
| 재사용 | 다른 그림·지역 코스 선택 | 난이도·테마 추천 | 반복 코스의 추가 거리 표시 |

## 7. 차량 특화성과 차별성

### 스마트폰 GPS 아트와의 차이

| 구분 | 일반 GPS 기록·수동 경유지 | Drive Canvas |
|---|---|---|
| 경로 작성 | 사용자가 지도에서 직접 설계 | 도로 제약과 그림 유사도를 함께 최적화 |
| 차량 연결 | 별도 앱과 내비 사이를 오감 | 차량 내비 경로·주행 상태와 연결 |
| 주행 중 경험 | 휴대전화 화면과 알림에 의존 | 차량 화면의 최소 정보와 음성 안내 |
| 경로 이탈 | 단순 재탐색으로 그림이 깨짐 | 안전 우선 재탐색 후 복원 가능성 판단 |
| 결과 | 이동 선 기록 | 목표 대비 완성도, 타임랩스, 공유 카드 |

차량특화성의 핵심은 큰 화면에 지도를 보여 주는 데 있지 않다. `차량에 적합한 경로 생성 → 차량 내비게이션에 전달 → 주행 상태에 맞춘 상호작용 제한 → 정차 후 결과 공개`가 하나의 닫힌 경험으로 이어지는 점이다.

## 8. 기술 구성과 Pleos 활용

아래 항목은 기획 단계의 기술 가설이며 실제 SDK 문서, 권한, 경유지 제한과 에뮬레이터 동작을 검증한 뒤 확정한다.

| 기능 | 기술 후보 | 역할 | 현재 상태 |
|---|---|---|---|
| 경로 시작·경유지 전달 | NaviHelper SDK | 생성한 경유지와 목적지를 차량 내비게이션에 설정 | SDK 기능·제한 검증 필요 |
| 주행 상태·TBT·재탐색 | NaviHelper SDK | 안내 진행, 경로 이탈과 도착 상태 수신 | 실경로 이벤트 검증 필요 |
| 실제 궤적 기록 | FusedLocation SDK 또는 허용된 위치 API | 위치 업데이트를 저장해 결과 선 생성 | 정확도·백그라운드 정책 검증 필요 |
| 음성 안내 | 차량 내비게이션 안내, 필요 시 TextToSpeech SDK | 화면을 보지 않는 최소 피드백 | 중복 음성 방지 설계 필요 |
| 차량 정차 판정 | AAOS 차량 상태 또는 제공 가능한 Vehicle SDK 신호 | 편집·결과·공유 기능의 주행 중 잠금 | 권한과 앱 정책 검증 필요 |
| 코스 적합성 | 도로 그래프·라우팅 엔진 | 방향·회전·도로 등급을 지키는 후보 생성 | 데이터 제공 조건과 라이선스 검토 필요 |
| 그림 유사도 | 자체 경로 최적화 알고리즘 | 목표 선과 실제 도로 경로의 거리·형태 비교 | 핵심 기술 실험 필요 |

### 경로 생성 개념

1. 하트 같은 정규화된 벡터 템플릿을 선택 지역의 크기와 방향에 맞춰 배치한다.
2. 템플릿의 특징점을 주변 도로 노드 후보에 투영한다.
3. 후보 노드 사이를 실제 주행 가능한 방향성 도로 그래프로 연결한다.
4. `형태 오차 + 추가 거리 + 위험 회전 + 좁은 도로 + 반복 구간` 비용을 최소화한다.
5. 경유지 수 제한에 맞게 특징점을 단순화하고 실제 라우팅 결과로 다시 채점한다.
6. 안전 기준을 통과한 후보만 내비게이션에 전달한다.

### 실패 대응

- 해당 지역에서 모양이 나오지 않으면 억지 경로를 만들지 않고 지역 범위 확대 또는 다른 템플릿을 제안한다.
- 경유지 제한을 초과하면 모양을 단순화하고 예상 유사도 하락을 출발 전에 표시한다.
- 위치 또는 내비 권한이 없으면 주행을 시작하지 않고 미리 제작된 코스 탐색만 제공한다.
- 네트워크가 끊기면 새 경로 생성은 중단하고, 이미 차량 내비에 전달된 안전한 경로의 종료를 우선한다.

## 9. 안전·개인정보·환경 설계

### 운전자 주의분산 방지

- 템플릿 선택, 후보 비교, 결과 상세, 공유는 정차 상태에서만 제공한다.
- 주행 중 지도에는 그림 전체보다 현재 안내와 단순 진행률을 우선한다.
- 경로 이탈 시 그림 완성을 위해 급한 복귀나 유턴을 요구하지 않는다.
- 코스 생성 단계에서 반복 좌·우회전, 주거 골목, 어린이 보호구역의 불필요한 통과, 사고 다발·공사 구간 등 사용 가능한 위험 정보를 비용 또는 제외 조건으로 반영한다.
- 앱은 교통법규 준수와 운전자 판단이 그림 완성보다 우선함을 명확히 안내한다.

### 개인정보 보호

- GPS 궤적은 기본적으로 기기 내에 저장한다.
- 집과 직장으로 추정되는 시작·종료 지점은 공유 이미지에서 자동으로 흐리거나 잘라낸다.
- 공개 코스 업로드는 명시적 동의를 받고, 원본 시간 정보 제거와 위치 단순화 옵션을 제공한다.
- 위치 기록 보존 기간과 삭제 기능을 사용자가 직접 관리한다.

### 환경 우려 대응

- 주행 전 추가 거리, 예상 에너지 사용을 표시한다.
- 기존 목적지 주변에 짧은 그림을 붙이는 `에코 우선`을 기본 후보 중 하나로 제공한다.
- EV 충전·관광·일상 목적지를 포함한 코스를 우선 제안한다.
- 서비스 메시지는 무제한 주행 경쟁이 아니라 계획된 여가 이동과 지역 체험에 둔다.

## 10. MVP 범위와 데모

### MVP 포함

- 하트 템플릿 1개
- 사전 선정한 검증 지역 1곳
- 30~45분, 출발지 복귀형 코스 1~2개
- 경유지 기반 내비게이션 안내
- 실제 또는 위치 시뮬레이션 궤적 기록
- 목표 선 대비 완주율·유사도 계산
- 정차 후 결과 화면과 공유 카드
- 경로 이탈 시 안전 우선 종료 흐름

### MVP 제외

- 사용자의 자유 손그림과 모든 문자 자동 생성
- 전국 어느 위치에서나 즉시 생성
- 실시간 다중 차량 협업 그림
- 사용자 제작 코스 공개 마켓
- 주행 중 게임 점수와 경쟁 알림
- 결제·광고·브랜드 캠페인 운영 기능

### 60초 데모 시나리오

1. 정차 화면에서 `하트`, `약 35분`, `출발지 복귀`를 선택한다.
2. 앱이 모양 우선과 시간 우선 두 후보를 지도에 보여 준다.
3. 사용자가 시간 우선 코스를 골라 차량 내비게이션 안내를 시작한다.
4. 위치 시뮬레이션에 따라 최소 주행 화면의 진행률과 TBT가 갱신된다.
5. 한 차례 경로 이탈에서 무리한 복귀 대신 안전한 종료 경로를 선택하는 모습을 보여 준다.
6. 정차 후 실제 궤적이 하트로 그려지고 완주 카드가 생성된다.

핵심 데모 증거는 화려한 템플릿 수가 아니라 `그림 → 실제 주행 가능 경로 → 차량 안내 → 실제 궤적 결과`가 한 번 연결되는 것이다.

## 11. 사업성과 확장성

### 단계별 확장

1. 개인용 템플릿 코스: 하트·별·이니셜과 완주 기록
2. 지역 관광: 지역 상징, 명소, 상점, 충전소를 포함한 공식 코스
3. 시즌 콘텐츠: 벚꽃, 크리스마스, 프로포즈, 생일, 스포츠 응원 코스
4. 브랜드 캠페인: 로고·캐릭터 IP 코스와 디지털 배지
5. 커뮤니티: 검수된 사용자 코스와 난이도·안전 피드백

### 수익 모델 가설

- 지역 관광기관과의 코스 제작·캠페인 계약
- 캐릭터·브랜드 테마 코스 판매 또는 스폰서십
- 고급 템플릿, 영상 내보내기, 기념 카드 꾸미기의 선택형 구매
- 완주 기반 지역 쿠폰과 제휴 수수료

초기 MVP는 결제보다 재사용성과 안전한 완주 가능성을 먼저 검증한다.

## 12. 성과 지표

| 단계 | 핵심 지표 | 의미 |
|---|---|---|
| 탐색 | 후보 생성 성공률 | 선택 지역에서 안전 기준을 통과한 경로를 만들 수 있는가 |
| 선택 | 생성 후 주행 시작률 | 결과가 실제로 달리고 싶을 만큼 매력적인가 |
| 주행 | 안전한 완주율 | 위험 복귀 없이 코스를 종료할 수 있는가 |
| 결과 | 그림 인지율·형태 유사도 | 다른 사람이 결과를 의도한 모양으로 알아보는가 |
| 공유 | 완주 카드 저장·공유율 | 결과가 콘텐츠 가치를 가지는가 |
| 유지 | 30일 내 두 번째 코스 실행률 | 일회성 이벤트를 넘어 재사용되는가 |
| 지역 | 경유지 방문·쿠폰 사용률 | 관광 코스가 실제 방문으로 이어지는가 |

효과 수치는 사용자 테스트 전에는 목표값으로만 두고, 실제 측정 결과와 구분한다.

## 13. 공모전 평가 관점의 자체 진단

| 영역 | 잠정 점수(5점) | 근거 | 보완 과제 |
|---|---:|---|---|
| 차량특화성 | 4 | 차량 내비 경로·주행 상태·정차 제한이 핵심 흐름에 연결됨 | 단순 모바일 경유지 앱과의 차이를 실제 시연으로 증명 |
| 창의성 | 4 | 내비게이션의 최단경로 역할을 생성형 드라이브 콘텐츠로 전환 | 자동차 GPS 아트 사례와 경쟁 서비스 조사 필요 |
| 기술 활용성 | 3 | NaviHelper·위치·차량 상태를 연결할 여지가 큼 | 경유지 제한과 도로 그래프 최적화의 실현 가능성 검증 필요 |
| 사업성 | 3 | 관광·브랜드 캠페인 확장 경로가 있음 | 반복 사용 동기와 파트너 비용 지불 의사 검증 필요 |

현재 총평은 `기획 초안으로는 강하지만 핵심 경로 생성 증거가 없으면 콘셉트 앱으로 보일 위험이 큰 후보`다. 하트 한 개를 실제 경로와 내비 안내로 연결하는 기술 스파이크가 다음 의사결정의 선결 조건이다.

## 14. 주요 리스크와 검증 과제

| 우선순위 | 리스크 | 실패 신호 | 대응 또는 축소안 |
|---:|---|---|---|
| 1 | 도로망 위에서 모양과 주행성을 동시에 확보하기 어려움 | 테스트 지역 대부분에서 알아보기 어려운 결과 | 전국 자동 생성 대신 검수된 지역 코스로 MVP 축소 |
| 2 | NaviHelper 경유지·재탐색 제약 | 생성 경로와 실제 안내 경로가 크게 다름 | 경유지 단순화, 사전 검증 코스, 허용 범위 내 분할 안내 검토 |
| 3 | 운전자 주의분산 정책 | 주행 중 필요한 화면이 앱 심사 기준을 넘음 | 주행 화면을 TBT·진행률만 남기고 상세 결과는 정차 후 제공 |
| 4 | 일회성 사용 | 첫 완주 후 재사용 의향이 낮음 | 지역·시즌 코스, 가족 미션, 목적지 결합 모드 검증 |
| 5 | 환경적 반감 | 불필요한 주행이라는 사용자 반응 | 추가 거리 표시, 에코 우선, 관광·충전 목적 결합 |
| 6 | 위치정보 노출 | 집·직장 위치가 공유 카드에 드러남 | 시작·종료 지점 자동 마스킹과 로컬 저장 기본값 |

## 15. 개발 로드맵

### 0단계 — 가능성 검증

- 하트 벡터를 특정 지역 도로에 수동·반자동으로 투영
- 라우팅 결과와 그림 유사도 비교
- NaviHelper 경유지 수, 순서 보존, 재탐색, 도착 이벤트 확인
- 주행 중 허용 UI와 정차 판정 방식 확인

### 1단계 — 데모 MVP

- 사전 선정 지역과 하트 템플릿 고정
- 경로 선택, 안내 시작, 위치 기록, 완주 결과 연결
- 정상 완주와 경로 이탈의 두 시나리오 구현

### 2단계 — 생성 기능 강화

- 별·글자 등 템플릿 확대
- 시간·유사도·도로 난이도 다목적 최적화
- 여러 지역 자동 탐색과 생성 실패 설명

### 3단계 — 서비스 검증

- 사용자 5~10명의 코스 선택·완주·결과 인지 테스트
- 두 번째 코스 실행 의향과 실제 재사용 측정
- 관광기관 또는 지역 파트너 인터뷰

## 16. 다음 의사결정

다음 세 조건을 만족하면 프로토타입 단계로 진행한다.

1. 사전 선정 지역에서 안전 기준을 통과한 하트 코스가 생성된다.
2. 생성 경로를 차량 내비게이션 안내로 전달해 의도한 순서로 주행할 수 있다.
3. 제3자가 완주 궤적을 보고 목표 그림을 알아볼 수 있다.

하나라도 충족하지 못하면 `전국 자동 생성` 주장을 제거하고, 사람이 검수한 지역 관광 GPS 아트 코스 플랫폼으로 범위를 줄여 다시 평가한다.
